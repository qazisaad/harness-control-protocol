# Native MCP detachment

Apps can use the existing `tool_servers.detach` command (SDK `detachTools`) when the selected execution profile advertises `mcp_detach: "idle_session"`. Names must identify distinct selected servers. The command removes servers from the current execution owner; its ACK follows native confirmation and owned proxy cleanup. `mcp.status.updated` reports `detaching`, then `detached` for each confirmed removal. Identical completed command receipts replay without repeating controls.

The runner refuses detachment during an admitted root, native background work, unresolved closure or an outstanding durable review. Drivers also check their native callbacks and initialization state. New prompts are fenced while removal or cleanup is pending. A native result must identify exactly the removed names and complete remaining inventory. The runner then revokes dispatch for those toolsets and closes only their owned clients. Failed or missing proof retains an unknown outcome and prevents prompts or automatic removal retries; confirmed session shutdown remains available. Read-only diagnosis is retained.

Detachment does not rewrite the conversation's authorization descriptors or silently broaden its tools. A fresh execution owner has its own explicit selected-server request, verified under the retained configuration binding. Selecting the original servers can reattach them on that owner. This contract does not authorize adding or replacing catalogs in a running owner, and does not imply a setting was saved in user/project configuration.

Claude's pinned interactive implementation registers selected HTTP proxy servers with `setMcpServers` before offering the first prompt. It requires an empty initial native inventory, an exact registration receipt and connected server/endpoint readback. Launch-flag servers are outside that dynamic removal registry, so passing them as launch options would not provide the removal guarantee. Detachment verifies the original connected server names and proxy endpoints, requests a reduced dynamic set, checks its removal receipt and verifies the remaining native inventory again. Unknown servers, endpoints, errors and partial receipts refuse confirmation. Controls and registry sizes are bounded. No raw native control API is exposed to the app.

Only Claude interactive advertises this additional native control today. Codex and OpenCode still require confirmed unload for lifecycle detachment. The independent packed consumer uses the same public command with a separate custom adapter; native CLI acceptance is `HCP_NATIVE_LIVE=1 HCP_LIVE_PROVIDERS=claude HCP_LIVE_DETACH=1 node scripts/check-native-mcp-live.mjs`. Startup registration, live detachment, duplicate removal, follow-up, unload and explicit reattachment to the same native conversation are separate assertions. Broader catalog reconfiguration and authoritative provider-death recovery remain open.
