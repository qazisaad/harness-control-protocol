# Owned native-work history

Applications can read an owned child's native conversation with `harness.conversation.request` operation `{kind: "work", action: "history", work_id, expected_revision, cursor?, limit?}`. The SDK provides `readNativeWorkHistory(sessionId, workId, expectedRevision, page?)`. Read the work registry first; use its current revision and never supply arbitrary native thread identifiers.

The result is a work receipt with `action: "history"`, the exact work ID/revision, `source: "native"`, `owner_status: "active"` and the same bounded native/portable history page used by root conversations. Cursors bind to the native conversation and observed history hash. Large supported items use scoped content references. A changed work revision or history snapshot requires a fresh read.

Discovery advertises `native_work_history: "live_owner"` on verified execution profiles. This means the currently loaded native execution owner can authorize a transcript read. It does not promise recovery after provider death, unloaded or retired work, arbitrary native IDs, child resume/fork, or a model request. Missing capability is unavailable. Native implementations are Codex 0.160.0 interactive, Claude Code 2.1.289 with Agent SDK 0.3.267 interactive, and controlled OpenCode 1.18.34 background. These named versions are acceptance observations, not certification of arbitrary versions. Per-work support depends on a verified child conversation; shell tasks and parent continuation jobs have no subagent transcript.

Codex confirms the work registry mapping, original root, current child identity, parent/source ancestry and canonical workspace before and after reading. It borrows the exact owner's existing RPC transport and never initializes, resumes, steers, interrupts or unsubscribes the child. A 30-second manager deadline abandons only its read requests. Native history may have an empty item list while a turn is in progress; consumers combine history snapshots with separately owned progress events without inventing retained content.

Provider configuration and execution bindings are checked by the manager. Ownership loss, revision drift and unsupported profiles refuse success. Session unload and retained observation recovery remain separate controls; a saved work record alone cannot grant access to a child transcript.

OpenCode borrows its existing controlled server, verifies child parent/directory before and after the read, checks every message and part identity, and compares two bounded snapshots. It does not apply root session permission rules to a child or launch another server. The selected, read-back agent policy remains the native child's authority.

Claude requires a live, initialized task owner with an admitted local-agent launch. Its selected-environment SDK helper verifies the parent conversation/workspace and confirms the exact task identifier in the parent's subagent inventory. It reads that transcript twice, refuses changes or missing membership, and validates returned message ownership. Stopping or timing out this dedicated read helper stops only that helper, never the model query or child. The same SDK turn/portable projection is used for root and child histories.
## Retained inspection and child forks

Explicit `{kind: "work", action: "history", owner: "retained", work_id, expected_revision}` uses private durable native custody and a new bounded inspection transport. The SDK exposes `readRetainedNativeWorkHistory`. The result declares `owner_status: "retained"`; it does not restore execution or callback ownership, change child permissions, or remove closure uncertainty. Profiles separately advertise `retained_native_work_history`. Codex verifies native child parent/source/workspace; OpenCode also preserves the original controlled account; Claude uses the original root's SDK subagent inventory. Missing durable custody refuses access.

A profile advertising `native_work_fork` may accept `{kind: "work", action: "fork", work_id, expected_revision, expected_history_hash, target_session_id, continuation_group_key, last_turn_id?}`. The source must already have native terminal proof. A durable fence precedes dispatch, unknown outcomes never dispatch again, and a successful independent destination is retained with the original authorized root configuration. The SDK exposes `forkNativeWork`. Codex and OpenCode implement the control; Claude does not advertise child forks. A child fork does not resume the source child. See [the parity evidence](harness-parity.md) for completed versus pending installed-native checks.

## Lost-child terminal reconciliation

`reconcileNativeWork(sessionId, workId, expectedRevision)` requests native terminal proof for a lost child's exact durably admitted execution. Only profiles advertising `native_work_terminal_reconciliation` support this observational control. Codex checks two stable native snapshots, ancestry/workspace and the exact final native turn; a missing, active or superseded execution refuses reconciliation. It never sends cancellation or model requests.

A successful receipt advances the work revision and records native `completed`, `failed` or `cancelled` status with `owner_status: "unavailable"` and `session_closure: "unconfirmed"`. Immutable command receipts replay after restart. Stale revisions/custody refuse the result. Child termination does not prove root termination, descendant closure, shell-process closure or transport/callback recovery. Whole-session closure reconciliation remains a separate unfinished gate.

Installed OpenCode 1.18.34 anonymous public-model acceptance now verifies retained child reads and independent forks after runner restart without restoring source execution ownership. Forked native messages/parts receive new IDs; source history hashes still guard the requested mutation, and copied context is verified separately. Resume the destination with the original bound execution profile and authority. `scripts/check-retained-native-work-live.mjs` accepts an explicitly selected private completed acceptance workspace/state through `HCP_NATIVE_RETAINED_WORK_CWD` and `HCP_NATIVE_RETAINED_WORK_STATE`; enable it with `HCP_NATIVE_RETAINED_WORK_LIVE=1`, the original provider environment and an explicit model. It never resumes the source child.
