# Native MCP input through the runner proxy

`McpProxyServer` supports a connector returning `McpInputRequiredError` through the public `@harness-control/runner/mcp` entry point. The connector uses `parseMcpPendingInput` to describe its pending elicitation, sampling or roots input. The proxy preserves the upstream continuation privately and presents an opaque one-use continuation to the caller. On a valid reply, the connector's existing `callTool(name, arguments, grant, continuation)` receives the original pending state and validated responses.

Modern MCP callers use the protocol's multi-round-trip input contract. Older native clients use an owned stateful HTTP connection: the SDK's compatibility bridge issues the corresponding native request and retries the same handler with its response. Modern and legacy requests share the same tool definitions and result projection. A request cannot choose an arbitrary upstream continuation, another tool, different arguments or another legacy caller's ownership scope.

Responses must match every requested input ID and schema. Invalid replies do not consume a valid ticket. A valid ticket is consumed before upstream dispatch, so repeating the continuation cannot submit an answer twice, including after an unknown dispatch outcome. Each proxy bounds pending input to 128 continuations, 8 MiB in aggregate and five minutes; an upstream deadline can shorten that period. Individual pending input retains its existing 1 MiB bound. Legacy caller connections are bounded at 32. Closing an owned caller/proxy discards its pending ownership. Expiry, disconnect and owner loss do not invent an upstream user cancellation.

This bridge preserves existing attachment policy, lease/proof and tool-discovery contracts. It does not establish a missing native originating turn or subagent identity. Claude's native MCP form callback remains honestly session-scoped. Native background MCP attachment support still requires independent call/work ownership proof. URL elicitation is subject to each driver's supported forms; malformed legacy URL requests without a valid native representation refuse.

The opt-in native check is `HCP_NATIVE_LIVE=1 HCP_LIVE_MCP_PROXY=1 node scripts/check-claude-elicitation-live.mjs`. Its local connector exercises the production proxy and actual Claude CLI/SDK without contacting a remote tool service. `examples/mcp-proxy-consumer.mjs` exercises the packed public API through a real older MCP client. This evidence does not certify every third-party connector, native client version or provider platform.
