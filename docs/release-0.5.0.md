# 0.5.0 migration candidate

Current checkpoint: the coordinated unpublished 0.5.0 release gate passes **1,052 tests**, three opt-in skips and **259 corpus cases** (122 valid, 137 invalid). All three independently packed packages match the gated artifacts byte for byte. The private T3 consumer passes **109 pure checks**, scoped types and fresh Codex, Claude and controlled anonymous OpenCode factory acceptance against these final packages. OpenCode factory acceptance includes root fork, populated destination history, rollback to thread start and subsequent resume. Claude includes restoration in a new application session. Active T3 adapters have not been switched and no package has been published.

The tested generic HCP migration checkpoint covers the verified provider profiles and operation inventory; it is not a complete inventory of every native provider feature. Provider transport, native ownership, execution and child custody, supported conversation controls, callbacks, MCP, media/history hydration and native evidence are available through public packages. Remaining T3 work is application-owned production wiring, persistence and DTO/UI projection. Capability limits and refused or unknown native outcomes remain explicit; this is not a universal native-version, account or remote-service certification. Historical counts and excluded probes below retain their original evidence boundaries.

This is an unpublished coordinated candidate for `@harness-control/protocol`, `@harness-control/sdk` and `@harness-control/runner`. It is not a claim that the T3 migration is complete. See [harness-parity.md](harness-parity.md) for current evidence and open gates. Publication requires a separate instruction.

## Consumer changes

Upgrade all three packages and the generated message schema together. Remove mixed transitive protocol versions from the installation; the isolated T3 probe required a pnpm override to keep its SDK and runner dependencies on the same packed protocol. Verify the actual resolved dependency tree rather than relying on a top-level version declaration.

Known `hcp.v0` messages and events remain strictly validated. New known event types, control variants and optional profile fields are not accepted by an older strict schema. The unchanged envelope version does not make an old validator compatible with the new contracts. Deployment must coordinate runner, consumer SDK and schema adoption.

Native identity comes from verified native conversation and execution events. An HCP application turn can span several native phases. `native.execution.admitted` identifies an acknowledged native phase; `native.execution.completed` supplies its actual terminal outcome. Both retain the application origin. A native goal has a separate HCP admission linked to its native generation; neither the application turn ID nor the goal admission is a native turn ID.

Read capabilities for the selected installed provider and execution profile. Codex 0.160.0 interactive advertises native goals and phase outcomes. Other profiles must not receive these operations just because the protocol includes their schemas. Goal resume requires the observed native generation, preserves native objective/budget/usage and admits a new application origin. Read/pause/clear helpers wait for matching native result evidence; a command ACK alone does not confirm a goal mutation.

Retained child reads and independent forks require private custody and stable native history proof. A transcript does not restore an execution or permission callback owner. Terminal child reconciliation never certifies whole-session closure. Pending native dispatches, active jobs, unresolved mutations and lost callback ownership remain fenced through restart.

Use `readNativeWorkInventory` for a stable complete retained roster, preserving original-turn/revision/owner evidence and unconfirmed closure. It refuses mixed, missing or duplicate pages. Use `readNativeWorkHistoryPageComplete` for integrity-checked child history content, selecting `owner: "retained"` after unload. Its `{work, history}` result keeps native custody proof and page fidelity/truncation/cursor; neither an empty roster nor a hydrated page certifies execution closure or a complete conversation.

Register `waitForSessionEvent` before dispatch to observe native proof separately from a command ACK. Its default boundary excludes old events; explicit `afterSequence` allows retained replay. Correlate original turn and actual native identity/generation in the predicate. Failed observation requires reconciliation and does not cancel execution or retry a mutation. Predicates and returned events cannot mutate the retained evidence through their arguments.

Native options and authority changes are explicit. Codex service tiers and automatic approval review preserve actual native readback. Claude Boolean thinking/fast-mode/ultracode controls require verified native settings; settings removal and native downgrade are observable. MCP catalog transitions preserve original non-tool authority and native history. Do not map unsupported product options or raw native policy overrides to silently ignored fields.
