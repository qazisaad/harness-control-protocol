# Owned input files

Apps can upload files through `harness.conversation.request` with `kind: "input_file"`. The SDK exposes `HcpHostConnection.inputFile(sessionId, request, command, wait)`. Uploads require an active authorized session, including a session that has not sent its first model prompt.

1. `create` declares a single display filename, MIME type, byte length and SHA-256. Keep the returned opaque `reference` and the original command identity. A retry with different metadata is refused.
2. `append` supplies an exact byte offset and canonical base64, in chunks of at most 64 KiB. Identical chunk retries are safe; overlapping changes, missing ranges and overflow are refused. `read` reports the current received byte count after reconnecting.
3. `seal` verifies the complete byte length and SHA-256. Partial uploads cannot be delivered to a model.
4. Send `harness.turn.send.files: [{reference, delivery: "file_context"}]` to select a sealed file. Sending a reference does not authorize an arbitrary host path or URL. Every reference field must match the original upload.
5. `release` removes an unused upload. Delivered files remain retained for conversation history and background work. Stop the owner and explicitly retire its conversation when those references are no longer needed.

Discovery reports `execution_capabilities.file_inputs`. The current Codex, Claude Code and OpenCode drivers declare `file_context`, a maximum of eight selected files per prompt and 32 MiB per file. This delivers a regular workspace file and a JSON description in the user prompt. The model reads it using its normal native tools and approval rules. MIME labels describe the supplied data; they do not establish that a provider can decode a format. `delivery: "native"` is refused before native prompt dispatch. Native image inputs remain a separate model capability and contract.

The runner privately retains the uploaded bytes and materializes selected files under the authorized working directory's `.hcp-inputs/<opaque-id>/`. Display filenames never select directories or commands. Consumers should exclude `.hcp-inputs/` from their source-change displays, search indexing and commits. Creating these paths does not grant additional sandbox permissions or make a full-access native process a filesystem sandbox. Filesystem symlinks, junctions, hard links, mismatched scopes and changed file bytes fail validation.

Ownership includes the conversation key (or ephemeral session identity), provider configuration binding, workspace and canonical working directory. The same retained conversation may reuse a reference after HCP session unload and runner restart. Other conversations cannot adopt it. Before a native fork dispatch, HCP pins history-visible files for the destination too. Retirement removes only the retiring ownership; the original native path survives until all owning conversations are retired. An uncertain fork outcome retains its pin and mutation fence rather than risking deletion from a possibly created conversation.

The store reserves declared sizes, with a 256 MiB aggregate and 1,024-file bound. It never evicts delivered files on root completion, expiration or quota pressure. Quota exhaustion requires the app to release unused uploads or retire idle conversations. Ephemeral session inputs are cleaned up only after successful native shutdown and confirmed work closure. Durable conversation inputs survive shutdown until explicit retirement. A failed or uncertain shutdown keeps their paths available.

Production `JsonRunnerStateStore` uses a sibling input store beside its retained content directory. `MemoryRunnerStateStore` retains inputs for the life of that store object; it does not promise process-restart durability. Integrators can supply `OwnedHarnessInputFileStore` through `HarnessSessionManagerOptions.inputFileStore`. The runner requires an exclusive owner for its state/input store. Applications own upload authorization, user-facing retention policy, previews and attachment product identifiers.

Retirement first closes the native ownership boundary and removes the native continuation binding, then performs owned file cleanup. Filesystem cleanup failures are reported; unrelated files are never recursively removed. Failed cleanup may leave storage that needs operator reconciliation. No cleanup failure may resume retired native work automatically.

`scripts/check-input-files-live.mjs` exercises pre-prompt upload, native file-tool reading, refusal of unsupported native document delivery, restart retention and retirement cleanup. `HCP_LIVE_FORK=1` additionally checks native fork retention after source retirement. These checks require `HCP_NATIVE_LIVE=1`, an authenticated CLI and a selected `HCP_LIVE_PROVIDER` of `codex`, `claude` or `opencode`.
